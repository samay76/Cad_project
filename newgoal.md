## Prompt

You are cleaning up and productionising `~/Cad_project`. The product is **one web application** that does three
things and nothing else:

1. **Teach**: load a part's STEP file in the browser, see it seated on the fixture, mark the two pick points (and
   optionally adjust the gripper pose with Step Jogging / Pick Offset).
2. **Simulate**: plan the grasp and run it in MuJoCo (plan, preview, sim run), with the result shown in the web app.
3. **Run on the real robot**: drive the real Elite EC66 + Robotiq 2F-85 through the same plan ("Real Sim", Go Home),
   mirrored live in MuJoCo.

Everything that is not needed for these three things is removed. The result must be safe and maintainable enough to
run in production on the cell PC.

### Production stack (target)

```
cad-pick-cell/
  web/                      TypeScript + Vite + Three.js (the current src/, public/, index.html)
  server/                   Python backend (FastAPI + uvicorn) - replaces the Vite dev-server bridge
    api.py                  same endpoints as mujocoBridge.ts today: /api/plan, /api/run, /api/real, /api/home,
                            /api/status, /api/stop, /api/fixture, /api/file
    jobs.py                 one job at a time (sim or real), job state, cancel = robot stop
  cell/                     the current jenga_mujoco/ package (sim + planner + real robot), as an importable package
    sim/  planning/  robot/  config/
  models/                   ec66, robotiq_2f85 (MuJoCo XML + meshes), table and fixture STEP
  tests/                    pytest (planner, fixture seating, grasp test plan, real_robot with FakeEC66/FakeGripper)
                            + one Playwright smoke test of the web app
  deploy/                   systemd unit(s), .env.example, install script
  README.md                 install, run, calibrate, safety
```

1. **Replace the Vite dev server as the backend.** Today the Python jobs are started from a Vite plugin, so the
   product only runs with `npm run dev`. Move the endpoints of `vite-plugins/mujocoBridge.ts` to a small FastAPI
   server that runs the planner and robot code as subprocesses or in-process jobs. Build the web app with
   `npm run build` and serve `web/dist` from the same server. Keep the request and response JSON exactly the same,
   so the web code only changes its base URL.
2. **Remove `localFileServerPlugin` in `vite.config.ts`.** It serves **any file on the PC** by absolute path
   (`/home/...`), and `server.fs.allow` includes `/home/human`. That is a security hole. Serve only the build output
   and the run folder files through `/api/file` with the name check it already has.
3. **Configuration:**
   - one `config/cell.json` (today's `sim_config.json`) plus `.env` for machine settings (Python path, robot IP
     `192.168.1.200`, gripper port `/dev/ttyUSB0`, host/port)
   - no hard-coded `~/miniforge3/envs/...` paths
   - validate the config at start-up (pydantic) and refuse to start on bad values
4. **Python environment:** one pinned `environment.yml` / `requirements.txt` for `mujoco_cad` (mujoco 3.x, numpy,
   scipy, trimesh, coacd, cadquery/OCP, fastapi, uvicorn, pyserial). Remove the separate `realsense_cam` env if the
   camera scan goes.
5. **Runs and caches:**
   - `runs/` gets an automatic clean-up (keep the last N runs or N days, setting in config)
   - `assets/` caches are rebuilt on demand and git-ignored
6. **Logging:** structured logs per run (`runs/<id>/log.txt` + the status JSON). For every real run, log the robot
   joints at each stop, the gripper result and the closed width, so sim-to-real comparisons can be made later.
7. **Safety for the real robot** (keep everything that exists, make it explicit and tested):
   - REMOTE mode check
   - stop on web Stop / window close / any error
   - joint-limit and path check before moving
   - `match_turns`
   - speed cap (`REAL_SPEED_MAX`)
   - arrival tolerance
   - gripper timeout
   - only one job at a time
   - Go Home before Real Sim

   Add a dry-run (`FakeEC66` / `FakeGripper`) test for each of these.
8. **Git hygiene:**
   - `.gitignore` for `runs/`, `assets/`, `dist/`, `node_modules/`, `__pycache__/`, `*.TXT` logs
   - large STEP files (`Table_base.step` 39 MB) in Git LFS
   - commit the work in progress on the current branch first, so nothing is lost
9. **Docs:**
   - one `README.md`: what the cell does, install, start, teach → sim → real, calibrate (`calibrate_robot.py`),
     fixture / new parts (each part's STEP must be in the fixture's coordinate frame), grasp test, safety, and
     troubleshooting messages
   - merge the useful parts of `jenga_mujoco/CAD_SIM.md` into it; delete the rest
